# The 1070 shooting session — runbook and eye-test checklist

Shooting happens ONLY here, ONLY in a session the owner asked for, and ONLY in the off-screen, MUTED test Chrome.
Box facts come from the fleet runbook (`~/.claude/projects/-home-wbterminal/memory/fleet-runbooks.md`, read-only —
re-read it before a session; it wins over this page).

## 1. The box and its rules

- `young@100.127.215.75` (tailscale, key auth), Windows, GTX 1070 — the fleet's only real GPU and the owner's
  baseline. **A person uses it**: everything stays off-screen; never touch their own Chrome or audio.
- Box shell is `cmd.exe` (chain with `&`, not `;`); `wmic` is gone (use `Get-CimInstance`); scratch files go to
  `D:\Temp` (the launch scripts stay in `C:\Temp`).
- Chrome launched straight from SSH gets no GL context (black 3D) — launch it in the INTERACTIVE session with
  `schtasks` (below).
- No sound may reach the person: the test Chrome always runs with `--mute-audio`; `boot` also silences the page's
  own audio graph. Never OS-mute the box (that mutes the person).

## 2. Pre-flight on the laptop (offline, before touching the box)

1. `free -m` — ≥ 2.5 GB available; no JS gate, build or other film command running (film commands hold
   `/tmp/hb-heavy.lock`).
2. `$FILM doctor --offline` — node, ffmpeg, playwright-core, JEV key (or none = code policy), gazetteer, disk.
3. ACE is up: `ss -ulpn | grep -E ':900[01]'` (vanilla ACE runs on this laptop; never edit or rebuild it).
4. serve.py is serving the live tree on :8765 (`ss -ltnp | grep 8765`). It is the owner's dev server
   (`external/holtburger/scripts/serve.py`; `--check` validates the baked layers). Never shoot through
   `--allow-missing` — it silently serves a partial world.
5. The wasm `pkg/` matches the source (a stale pkg boots silently broken; film code typeof-guards every wasm
   export, so a missing export shows up as a degraded feature, not an error). The session never rebuilds it — if a
   rebuild is needed, stop and tell the owner (wasm builds are a capped heavy job).
6. The plan is validated and compiled (`timeline.json` exists); you know the site order (`plan compile` prints it).

## 3. Bring up the test Chrome and the tunnel

Test Chrome (interactive session, via a one-shot scheduled task; `launch-wls.bat` already carries the flags):

```bash
ssh young@100.127.215.75 "schtasks /create /tn X /tr C:\Temp\launch-wls.bat /sc once /st 00:00 /it /f & schtasks /run /tn X"
# launch-wls.bat: chrome --remote-debugging-port=9333 --use-angle=d3d11 --ignore-gpu-blocklist --mute-audio
#                 --user-data-dir=C:\Temp\cdpwb-wls --window-position=-32000,-32000 about:blank
```

Tunnel — THREE forwards (CDP to the laptop; the page and the ws↔UDP bridge back to the box), no `timeout` wrapper:

```bash
ssh -o ExitOnForwardFailure=yes -fN -L 9333:127.0.0.1:9333 -R 8765:127.0.0.1:8765 -R 8080:127.0.0.1:8080 young@100.127.215.75
curl -s http://127.0.0.1:9333/json/version     # Chrome answers through the tunnel
```

- `-L 9333` — the CLI's `--cdp=http://127.0.0.1:9333` (default) reaches the box's Chrome.
- `-R 8765` — the box's `http://127.0.0.1:8765/apps/holtburger-web/index.html` (the CLI's default `--base`) is the
  laptop's serve.py.
- `-R 8080` — the client's default `bridge_url ws://127.0.0.1:8080/` reaches the laptop's `holtburger-wsbridge`
  (auto-supervised) → ACE. Without it login dies with `WsTransport ws handshake failed` and `__bootState='error'`.

`$FILM doctor` (without `--offline`) prints exactly this line when CDP does not answer (also as `result.tunnel`
with `--json`); `--host=<user@ip>` or env `FILM_1070_HOST` changes the box, and the `-L` port follows `--cdp`.

## 4. Check, boot, shoot

```bash
$FILM browser check                         # exit 1 = Chrome without --mute-audio, or the film window ON SCREEN
FILM_PASSWORD='…' $FILM boot --assume-muted  # password from the owner, typed at run time — never saved
```

`browser check` prints the pages (passwords redacted), whether a film page is open and booted, the mute state
(`verified` / `absent` / `unverified` — Chrome reports its command line only with `--enable-automation`, which the
launch script does not pass, hence `--assume-muted`), the window bounds (off-screen = left/top ≤ −10000 or
minimised) and the GPU string. The renderer must be the real GPU (`ANGLE (NVIDIA … GTX 1070 … Direct3D11)`); a
`SwiftShader`/`llvmpipe` warning means you are not on the 1070's GPU — stop.

`boot` attaches (never launches), refuses without mute, refuses a second film tab (`--reuse` adopts it — the account
is single-login), opens a new tab in the default context, sets the exact viewport (CDP device metrics, 1920×1080
by default — the canvas latches its size at boot), installs the JEV broker (`window.__filmJev`), and navigates to:

```
http://127.0.0.1:8765/apps/holtburger-web/index.html?nosw=1&agent=1&hud=none&plugins=none&filmMode=on&filmDof=on
  &filmProps=on&autoLogin=1&account=phase4demo&password=<run-time>&autoSpawn=first&quality=ultra&renderScale=1
  &adaptiveRes=off&radialFog=on&objRadius=off&fogRingCap=off&punchSidedness=on&particleClock=sim&frameBudget=off
  &maxTickDist=400&dynLod=off&clouds=on&cloudWeather=off&cloudCoverage=0.3&stormScan=retail&waterSheenFade=40,500
```

| Params | Why |
|---|---|
| `nosw=1` | bypass the service worker cache (it caches index.html and code across reloads) |
| `agent=1&hud=none&plugins=none` | canvas only, no HUD/plugins — the clean frame starts at boot |
| `filmMode=on&filmDof=on` | load the film runtime (`window.__film`) and build the depth-of-field effect (`window.__dof`); both exact `=== "on"` opt-ins, default off |
| `filmProps=on` | arm the lens overlay (FPV propellers at the top of the frame, drawn after all post effects); exact `=== "on"` opt-in; it draws only for a take whose plan shot has `overlay.props` |
| `autoLogin=1&account=phase4demo&password=…&autoSpawn=first` | headless login as the film account |
| `quality=ultra&renderScale=1&adaptiveRes=off` | fixed preset and exact pixel size (no adaptive resolution). `ultra` by default since 2026-10-15 (stepped capture is not real-time bound; the owner's look passes were at ultra: 2× grass, ice refraction, wet mud, marsh wisps, more particles); `film boot --quality=high` (or low/mid) overrides |
| `radialFog=on&objRadius=off&fogRingCap=off&punchSidedness=on` | retail range fog; objects and the PVS ring not trimmed to a near radius / the fog band; retail portal sidedness |
| `particleClock=sim&frameBudget=off&maxTickDist=400&dynLod=off` | particles on the sim clock (the film clock drives it in stepped takes); no per-frame async budget; entity anim/AI ticking out to 400 m; no distance despawn of entities |
| `clouds=on` | volumetric clouds (owner 2026-10-14: always on for film) and the split post chain, so depth of field blurs the finished atmosphere; `film boot --clouds=off` leaves it out (GPU-heavy) |
| `cloudWeather=off` | fair-weather clouds frozen (owner 2026-10-14: sun out) — a stormy server DayGroup would otherwise switch to the storm deck + 10× haze and make every take overcast; `film boot --weather=live` follows the server weather |
| `cloudCoverage=0.3` | cloud coverage 0..1: `0.3` by default with fair-weather clouds; `film boot --coverage=<0..1>` sets it (always included when given, also with `--weather=live` / `--clouds=off`); left out with live weather or no clouds otherwise |
| `stormScan=retail` | ALWAYS: retail's storm rule. The client's default `legacy` scan reports a storm every day, which gave every take the overcast deck, a permanent rain sheen, storm wind, and gated pollen / fireflies off |
| `waterSheenFade=40,500` | ALWAYS: water ripples / glint stay visible out to 500 m instead of 160 m (terrain.js; an older page ignores the param) |

Every take report records what the page actually ran with (`pageEnv` in `reports/<shot>.json`: the redacted URL,
the quality preset, `isStorm`, the cloud / storm / water URL values and whether the terrain water / IBL uniforms are
on) — check it when a take looks grey or stormy.

Boot gate: in-world (scalar or `__bootStateHistory`) AND `ready` AND `__sceneReadyEverFired` AND `liveScene3d` (it
arrives ≈ 35 s after in-world) AND `__film`; after 90 s a scene with > 100 meshes also counts (the SwiftShader
trap). An `error` before in-world is a login failure — "Account In Use" means wait ~25–65 s (ACE reaps an
abandoned session after ~60 s). `--boot-timeout=180` s by default. Then: page muted, `__film.clean(true)`,
`own()`, `world.avatar(false)`, `@cloak on`, `@attackable off`.

Every later command (`go`, `scout`, `rehearse`, `shoot`) re-applies the viewport (CDP overrides end with each CLI
process) and re-installs the broker. Then work site by site (reference/workflow.md §3): `go` → `scout` /
`rehearse` → `shoot --site=` → `contact-sheet` → Read.

Readiness (`go`, and the first step of each site in `shoot`): the teleport happened (portal seen, or a grace
period), portal space inactive, the target landblocks' terrain baked + attached + not parked, no
`terrain:|statics:|buildings:` stream keys in flight, the PVS sweep complete, interiors loaded (whenever the
destination cell is an EnvCell — dungeons, and towns/POIs whose teleport lands indoors, such as Kor-Gursha), the scene
counts unchanged for 3 × 500 ms, then `ready.settleSec`; never past `ready.timeoutSec`. `go` prints
`ready after N s (portal M s)` or `NOT READY` with every sub-check. Before each site's teleport `shoot` checks
`__film.status()` and aborts a take still running on the page (re-sending the abort on every poll while the page
stays busy, ≤ 30); it never teleports under a running take, and the page itself refuses `world.teleport` /
`world.command` with `FILM_BUSY` while a take, prepare, shoot, rehearse or scout runs.

## 5. Eye-test checklist (handoff §8 — owner-run, record pass/fail + the `$FILM status` JSON for each)

Boot as above at 1920×1080, `quality=ultra` (the default since 2026-10-15; earlier checklist runs used `high`),
account `phase4demo`. After each item run `$FILM status` (or
`$FILM status --json`) and record its output: `__film.status()` plus a probe of what the status lacks (the camera
switcher's `cameraMode`, `avatar.filmHidden`/`visible`, the `canvas` drawing buffer).

1. **HUD-free frame:** no toolbar, radar, chat, brackets, bubbles, cursor or canvas border; the canvas is exactly
   1920×1080 (`$FILM status` → `canvas 1920×1080`, read from `__renderScaleState().drawingBuffer`; `shoot` warns
   when the canvas differs from the timeline).
2. **`own()` / `release()`:** the camera holds the film pose; release restores follow mode, the avatar is visible,
   no stuck keys. `$FILM status --release` calls `__film.release()` → `clean(false)` → `world.avatar(true)` and
   checks through the status that the camera is free (follow restored), the frame is no longer clean (HUD back,
   input unlocked) and the avatar is not film-hidden — `release: follow restored yes · frame restored yes · avatar
   visible yes`, exit 1 when one is not. Look at the frame, then re-own with
   `$FILM status --own --clean=on --avatar=off` (the frame `boot` leaves; `@cloak`/`@attackable` are untouched).
3. **Straight-down tilt** (`classic.tilt` 0° → −90°) **and `drone.pass-over`:** no flip or jump at nadir; the
   yaw-slew reads as a smooth image rotation.
4. **Dungeon `fpv.fpv-corridor` through a 90° turn** (Holtburg Dungeon `0x01F6…`): rooms stay drawn (the film
   viewer cell is carried), no wall clipping, smooth heading through the turn.
5. **Pilot near trees** (Holtburg outskirts or Glenden Wood): JEV decisions logged (`reports/<shot>.jev.jsonl`:
   that shot's calls only, its rehearsal included; `<shot>.pilot.jsonl`), drift/rise chosen sensibly, no
   collisions (`safety.adjustedFrames` counted), the code-policy agreement rate (`pilot.agreement.rate`).
6. **Stepped take, 10 s @ 30 fps:** 300 frames, a playable mp4, foliage/water/particles animate at real speed (film
   clock), no hitch after the cut (pre-roll).
7. **Teleport + readiness:** `go` to a second site, ready report ≤ ~15 s, no pop-in in the next take.
8. **MANDATORY — depth of field (in v1 by owner decision):** with `?filmDof=on` (always in the boot URL),
   `classic.rack-focus` visibly pulls focus foreground → subject, no depth artefacts (log depth), no change at all
   with the flag off, a compile hitch only on first use.

A ready eye-test plan (validated 2026-10-14 — `plan validate` → `valid: 0 error(s), 0 warning(s)`; its `{sec}` route
shot dry-builds offline through a synthesized route, plan-format.md §10). Save it as `plan.json` in
a project (`$FILM project init film-eyetest`), compile, then `shoot timeline.json --all`; item 7 is the `go` into
`glenden`, items 1/2 use `$FILM status` (and `status --release` / `status --own …`), the rest map to shots.

## 6. Cleanup (end of every session)

1. Takes are on the laptop (`/mnt/wbterminal2/film-projects/<name>/`); nothing is stored on the box.
2. Close the film tab or leave it for the owner as they prefer; the film account stays logged in while the tab
   lives (single login). A tab left open can be handed back first with `$FILM status --release` (camera in follow
   mode, HUD and input back, avatar shown).
3. Stop ONLY the test Chrome, matched by its user-data-dir — never `taskkill /IM chrome.exe` (that kills the
   person's browser):
   ```bash
   ssh young@100.127.215.75 "powershell -NoProfile -Command \"Get-CimInstance Win32_Process | ? CommandLine -like '*cdpwb-wls*' | % { Stop-Process \$_.ProcessId -Force }\""
   ```
   (`\$_` keeps bash from expanding `$_`; PowerShell receives `$_.ProcessId`.)
4. Close the tunnel: find its pid with a pattern that cannot match your own command line, then kill that pid:
   `ps -eo pid,args | grep '[s]sh -o ExitOnForwardFailure=yes -fN -L 9333'` → `kill <pid>` (never
   `pkill -f <pattern>`; it can kill the shell running it).
5. Report to the owner: the eye-test items with pass/fail + status JSON, the project path, and anything left
   running.
