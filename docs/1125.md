## 3. Root cause of the user-visible freeze window

Stage decomposition (laptop real-render cold probe): land → sealed
detection ~5.5 s → **~12 s decode+spawn wave** (205 EnvCells ≈ +130 bake
requests + ~155-entity portal burst, worker starved by the render loop)
→ all 205 cells attach <1 s → **then a ~2,500-child outdoor statics
build** (t≈33–36 s+, `static-batch-c-*`/`stat-atlas-x-*`) for the
destination's OWN keep-ring — TN's ring is the world-edge mountain wall +
ocean skirt, scenery-heavy — queued behind the interior and executed
right in the player's first-input window, **entirely invisible** (it is
exactly what `sealedCull` hides). On weak/loaded hardware this build is
the wall the user hits; on a quiet 1070 it's absorbed.

## 4. The fix — `?sealedStaticsSkip` (default-ON, `off|0|false` escape)

While `_sealedEvictLbKey` is nonzero (the `sealedEvict` signal): (a)
`index.js loadStaticsForLandblock` returns before the fetch/guard-slot
claim (LB not marked baked — future non-sealed approaches build
normally); (b) a build already in flight when the seal engages aborts at
the statics **F3 cancellation guard** (geometries disposed, mark cleared,
nothing attached). Interior/EnvCell statics + scripts untouched; mouthed
dungeons never seal; a sealed dungeon has no mouth, so the only exit is a
portal whose arrival LB streams fresh — no deferred bookkeeping needed.
Files: scene3d/statics.js (`SEALED_STATICS_SKIP_ON`, `_sealedNow`, F3
`_sealedAbort`), scene3d/index.js (entry guard + import), url-flags row.
