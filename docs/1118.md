## 5. Wasm-threads (SAB) ballpark — 2-agent read-verified inventory

Multi-week: **1 XL + 2 L + several S/M**. Pre-shaped (~60%): shard cache
already `Arc<Mutex<HashMap<_, Vec<u8>>>>`, `Semaphore` already
thread-safe (std Mutex + oneshot, multi-thread-tested), `ResourceSource`
already `Send + Sync`, decode fns take the source as a param (only ~4 of
60 thread_local slots are decode-path). The hard parts:
- **XL — fetch/decode boundary split**: `inflight.rs:117-120` +
  `walk_dedup.rs:63-65` are `unsafe impl Send/Sync` over JS fetch futures,
  sound ONLY single-threaded; real threads make them silently unsound
  (compiler won't catch it). Clean fix = pin all `web_sys::fetch` to one
  owner thread, message-pass `Vec<u8>`.
- **L — toolchain bring-up**: nightly + build-std, `+atomics,+bulk-memory,
  +mutable-globals`, shared-memory link flags, worker-pool glue wasm-pack
  doesn't emit; dep-graph atomics compat unverified until it links.
- **L — `TEX_SWAP_ALIASES` identity semantics**: per-instance minted ID
  spaces are deliberately disjoint today (lib.rs:5905-5909 "never
  memoise"); a shared registry is a correctness redesign.
- Infra is CHEAP: COOP/COEP = two headers in serve.py `end_headers()` +
  proxy.cjs; all workers same-origin URL workers; WS bridge COEP-exempt;
  SW needs a v2→v3 cache bump (pre-header cached shards would silently
  break isolation = empty-world class); vendor the 4 jsdelivr importmap
  entries (three/postprocessing/tiny-invariant) like @takram already is.
  No prod hosting config exists beyond serve.py+proxy.cjs.
- Near-term levers stay: batch splitting → second worker (~2× ceiling on
  8 GB boxes, duplicated caches + 3-way alias split) → threads endgame.
