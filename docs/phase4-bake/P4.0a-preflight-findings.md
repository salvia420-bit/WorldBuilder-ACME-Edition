## 3. Second finding — UTF-8 BOM in the served catalog
`hadBom: true` — the C# emit writes a leading UTF-8 BOM. The **browser** `fetch().text()` strips a leading BOM
per the encoding spec, so the browser parses all 1168. But any **node-side** reader (tests, the new bake oracle)
that does `readFileSync(...,'utf8')` keeps the BOM → `JSON.parse` throws on line 1 → the first descriptor
(`0x02000006`) is silently dropped. **P4.0c's tolerant parser must strip a leading BOM**, and ideally the C#
emit should stop writing one (`UTF8Encoding(false)`). Recorded so the node golden/bake matches the browser.
