## 1. What landed (appendix item → code)

- **A3/B1 surface positive cache** (`?surfaceCache`, default-ON):
  `SurfacePixels` decodes are memoised per wasm instance in a NEW
  refcount-aware byte-budget LRU (`ByteBudgetLru`, lib.rs — the retail
  DBOCache discipline T13 specified): ~96 MiB budget, 16 MiB per-entry cap,
  `Arc`-valued behind `surface_memo_get/insert` accessors (T14 threads
  seam), keyed on the ORIGINAL requested DID. Insert gate = COMPLETENESS,
  not phase: per-DID `DecodeAuditSource` misses==0 && width>0 && not the
  magenta decode-fail sentinel — so the discovery walk's terminating
  complete decode is harvested (kills the guaranteed +1 final decode, T01)
  while partial dry-run rounds stay uncached (the MODEL_TRI_CACHE
  poison-guard lesson). Walk closures skip already-complete DIDs (kills
  the 2–8× walk re-decodes T12 bounded). All four surface exports route
  through it: `fetch_surface_pixels`, `fetch_surfaces_pixels` (positional
  partition + per-DID audits summed into the P2↔P3 `decodeMisses` ABI),
  `fetchEntitySurfacesPixels`, and the F.41 batch. Entity decodes share
  the cache ONLY when palette-free (base palette 0, no sub-palettes) —
  host-test-proven byte-identical to the static path; palette-composed
  (dyed) decodes bypass it entirely. Cleared on `init_resource_source`
  re-init; `surface_cache_clear()` export; `dat_decode_diag()` reports
  hits/misses/inserts/evictions/bytes/entries.
  - **Tex-swap aliases (0x08F0xxxx) ARE cached** — a mid-session
    correction: the first S5b live read showed mainAmp 4.66 with aliases
    excluded (the R-1 aliasSplit routes alias decodes to the main thread,
    so main's load is MOSTLY aliases → pure per-bake re-decode waste).
    Unlike the neg-cache (which refuses the block because absence is
    unprovable for a synthetic mint), the positive gate is safe: the
    per-instance alias registry is append-only — an alias's (base, tex)
    never remaps — so a complete alias decode is deterministic. Host test
    `alias_dids_are_positively_cached` pins it.
- **MODEL_TRI_CACHE eviction upgrade** (T13): the 4096-ENTRY
  clear-on-overflow (unaccounted hundreds of MiB potential; flushed
  everything on overflow) became the same `ByteBudgetLru` — 64 MiB
  byte-budget, 8 MiB entry cap, refcount-aware LRU, and it now CLEARS on
  `init_resource_source` re-init (previously survived re-init — a latent
  staleness hole). This attacks the 1121 §5b renderer-RSS growth class
  directly.
- **A5-wasm (T08)**: (i) `Environment::unpack` re-parse per sibling cell
  (the self-documented waste at the old lib.rs:16806) → per-call
  `env_record_cache` memo keyed by env DID (parse failures memoised too);
  (ii) cell-physics idempotency: `CELL_PHYSICS_PENDING` now carries one
  entry per CELL (its complete fan-triangulated set) and the drain calls
  NEW `SpatialScene::replace_cell_triangles` (scene.rs) instead of
  append-only `insert_cell_triangle` — a duplicate
  `fetchEnvCellsInLandblock` replaces byte-identical content instead of
  DOUBLING `cell_physics_index` (which inflated every per-tick
  `scene.clone()`). Composes with the existing LANDBLOCK_CLEAR_PENDING
  evict-clear (re-entry re-bake still replaces).
- **A11 decode batch-split** (`?batchSplit`, default-ON; owed since 1117
  §4): NORMAL-lane `fetch_surfaces_pixels` walks + decodes in chunks of 16
  DIDs (`batch_split_ranges`, host-test-pinned boundaries) so an urgent
  player-LB caller preempts at the next await boundary instead of behind a
  whole background batch. Urgent lane never splits. Chunks memo-insert as
  they complete → splitting adds no re-decode under B1. Bonus: the
  rewritten partition dedupes REQUESTED duplicates (the old final loop
  decoded per position).
- **A12 LOD degrade batch** (`?lodPrewarm`, default-ON): NEW wasm export
  `fetch_entity_degrade_for_distance_batch(setup_ids[], distances[])`
  (per-item failure → 0, never fails the wave; single export refactored
  onto a shared inner). spawns.js pre-warms a whole spawn wave in ONE call
  (same THREE-frame distance formula as `_spawnImpl`, skipped when no
  camera — matching _spawnImpl's own skip), results land in NEW
  `scene3d/lod_prewarm.js` (shared memo, 25 m distance buckets, bounded
  4096); `_spawnImpl` reads it synchronously and falls back to the
  per-entity call on any miss (pure perf layer; stale band picks
  self-correct via the T9 tick recheck as before).
- **A13a freeze-hash** (`?freezeHash`, default-ON): the advisory E5
  scenery determinism gate's per-cold-LB sidecar GET was awaited INLINE on
  the player-blocking path — now the FNV fold stays sync (cheap CPU) and
  the sidecar fetch + compare ride a detached `spawn_local` task;
  `=off` skips even that. WARN semantics unchanged.
- **A10 G2/G3 canaries + 5b wasm-memory canary**: `dat_decode_diag()`
  grows `surfaceDecodeTotal`/`surfaceDecodeDids` (G2 — bumped in both
  impls' `Ok(pixels)` arm in EVERY phase, walk waste included; census
  keyed on the REQUESTED DID so two aliases of one base aren't read as
  amplification; palette-composed entity decodes EXCLUDED — per-combo
  work with distinct outputs, not amplification), `hmBatchHist` (G3 —
  per-call batch-size histogram at `fetch_landblock_heightmaps` entry),
  `wasmMemoryBytes` (5b — `memory.buffer.byteLength`, the renderer-RSS
  growth observable), and the `surfaceCache*` block. ci-smoke gained

  worker relay: decodeAmp = total/distinct FAILs >1.15 (≥20-decode
  guard), heightmap solo share FAILs >0.25 — **LB-weighted** (soloLbs /

  wasm-memory MB in the PASS line. Auto-SKIP on a legacy pkg (fields
